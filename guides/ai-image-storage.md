# 대표 사진·AI 결과 내부 저장 구조

## 이번 변경 범위

원본 사진에 대표 여부를 추가하고 AI 생성 결과 테이블을 분리합니다. 프론트엔드 코드, 기존 URL·요청·응답 필드·Swagger 문서는 변경하지 않습니다. AI 모델 호출·새 HTTP API·관리자 화면은 포함하지 않습니다.

## 원본과 생성 결과

- `missing_person_images`: 경찰청 원본. `is_main`을 추가하고 기존 활성 사진 중 첫 순번을 대표로 초기화합니다.
- `missing_person_ai_images`: 아동 FK, 원본 FK, 목표 나이, 결과 파일·형식·크기, 대표 여부, 공통 시각만 저장합니다.
- `source_image_id`: 원본 레코드 참조입니다. 경찰청 입력 파일을 AI 테이블에 다시 복제하지 않습니다.
- `content`: AI 생성 결과입니다. 실제 모델 연동 전에는 실제 생성 결과가 자동으로 쌓이지 않습니다.
- 나이를 알 수 없는 원본 사진의 촬영 당시 나이, 별도 추정 나이, 모델 이름·버전은 저장하지 않습니다.
- 원본은 최대 2MB, AI 결과는 최대 10MB의 JPEG/PNG를 허용합니다. 결과 파일에서 형식·크기를 확인합니다.

## 내부 서비스

`MissingImageManagementService`는 HTTP로 노출하지 않는 내부 계약입니다.

| 메서드 | 역할 |
| --- | --- |
| `ensureOriginalMain(personId)` | 대표가 없을 때 첫 활성 원본 선택 |
| `selectOriginalMain(personId, imageId)` | 같은 아동의 활성 원본을 대표로 선택 |
| `saveAiResult(personId, sourceImageId, targetAge, generated)` | 같은 아동 원본을 참조해 AI 결과 저장. 첫 저장 결과를 대표로 지정 |
| `selectAiMain(personId, imageId)` | 같은 아동의 활성 AI 결과를 대표로 선택 |
| `deleteAiResult(personId, imageId)` | 소프트 삭제 후 남은 첫 결과를 대표로 선택 |

대표 원본·AI는 각각 최대 한 장입니다. 아동 행 잠금과 부분 UNIQUE 인덱스를 함께 사용하고, 이전 대표 해제·새 대표 지정은 같은 트랜잭션으로 처리합니다. 오류 시 이전 대표도 유지됩니다. 실제 관리자 HTTP API를 만들 때에는 관리자 권한 검증을 추가해야 합니다.

## 경찰청 재동기화

- 활성 대표 원본은 유지합니다. 대표가 원본 목록에서 제거되면 남은 첫 사진으로 재선정합니다.
- 사진 부분 실패만으로 기존 사진을 삭제하지 않습니다.
- AI 사진·목표 나이·대표 AI 선택은 경찰청 동기화에서 변경하지 않습니다.
- 원본을 소프트 삭제해도 기존 AI 결과와 원본 FK는 유지합니다.
- 원본 레코드의 파일은 경찰청 재동기화로 갱신될 수 있습니다. 별도의 원본 버전 스냅샷은 이번 범위에 포함하지 않습니다.

## API 유지

기존 `photoUrl`은 대표 원본 주소를 반환하고 `images`의 필드와 원본 순서는 유지합니다. `is_main`이나 AI 목록을 응답에 추가하지 않습니다. AI UUID를 기존 원본 사진 조회 URL에 넣어도 AI 결과가 노출되지 않습니다.

변경 전 OpenAPI JSON을 테스트 기준으로 저장하고 테스트 실행 주소를 제외한 경로·설명·요청·응답 스키마 전체를 비교합니다. AI 저장·조회 HTTP API는 다음 단계에서 별도로 설계해야 합니다.

## 적용·확인

백엔드를 재시작하면 Flyway V10이 기존 파일·UUID를 보존하며 대표값과 AI 테이블을 추가합니다. 개발용 원본·AI 저장과 동시성·롤백·이전 V9 업그레이드 검증은 임시 DB 통합 테스트로 실행합니다. 실제 AI 결과나 개인정보 파일은 문서 저장소에 넣지 않습니다.
